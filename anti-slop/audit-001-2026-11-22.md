# Anti-Slop UI Audit 001

Scope: current JEE portal HTML, generated cluster pages, practice pages, and active generators.

## Findings

1. **HIGH — Decorative emoji is used as interface decoration throughout the portal.**
   - Rule: R-04 / Emoji as Decoration.
   - Evidence: 32,678 emoji-like glyph occurrences across 2,592 HTML files, including repeated `📝`, `🔬`, `🔑`, `🌐`, `🚩`, and decorative arrows.
   - Reason: These marks compete with question content and make the interface feel generated rather than information-led.

2. **HIGH — The cluster-refresh control is not a complete interaction.**
   - Rule: R-26 / Non-Functional Controls.
   - Evidence: the active builder emits a button that POSTs to `/api/refresh-clusters`, but no matching API route/server handler exists in the repository; the current generated HTML contains no refresh control.
   - Reason: Users can click a control that cannot perform the promised refresh operation.

3. **HIGH — The project has multiple competing cluster-page generators with materially different markup and behavior.**
   - Rule: R-24 / Dead Navigation and C-2 / Functional Completeness.
   - Evidence: `build_everything_clean.py` and `generate_all_cluster_pages.py` both write the same cluster paths but produce different navigation, styling, answer behavior, and media handling.
   - Reason: Running one generator can silently remove functionality produced by the other, making the portal’s behavior non-deterministic.

4. **MEDIUM — The UI relies on repeated gradient header treatments without a documented design direction.**
   - Rule: R-01 / Purpose Test and R-29 / Palette Discipline.
   - Evidence: 715 `linear-gradient`/`radial-gradient` occurrences across generated HTML; no `DESIGN.md` or equivalent direction file exists.
   - Reason: The gradients currently read as a repeated default treatment rather than a purposeful hierarchy or product identity.

5. **MEDIUM — The portal does not have a documented visual direction or rationale for its dark-first theme.**
   - Rule: R-21 / Theme Choice and C-1 / Intentionality.
   - Evidence: no `DESIGN.md`, while cluster pages default to dark styling and practice pages contain several independent theme systems.
   - Reason: A working theme toggle exists in parts of the portal, but the visual system is not consistently governed across generators.

6. **MEDIUM — Inline event handlers and duplicated page-local scripts make interaction behavior difficult to keep consistent.**
   - Rule: R-26 / Non-Functional Controls and C-4 / Resilience.
   - Evidence: generated pages use large numbers of inline `onclick` handlers and separate local implementations such as `toggleAns`, `checkAnswer`, and `selectOption`.
   - Reason: The same interaction can diverge between chapter, cluster, bucket, and practice outputs and is harder to keyboard-test or maintain.

7. **LOW — The generated portal has no shared design-system source for typography, spacing, color, or focus states.**
   - Rule: R-06 / Typography, R-11 / Radius, and C-1 / Intentionality.
   - Evidence: styles are embedded independently in generated pages and scripts; the audit found 391 focus selectors across 2,592 HTML files rather than one shared source of truth.
   - Reason: Small visual and accessibility differences accumulate across page families.

## Suggested next order

1. Approve findings 2 and 3 first so refresh and cluster generation have one reliable source of truth.
2. Approve finding 1 and then remove only decorative emoji, preserving symbols that carry mathematical or status meaning.
3. Approve findings 4–7 for the visual-system and maintainability pass.
